# FluxEngine — Концепция и границы проекта (Vision / Product Brief)

## Что делаем

FluxEngine — игровой движок на Rust для разработки игр:
собственный рендер-стек (RHI + Vulkan/DX12), собственная архетипная ECS,
собственная физика на f64, полный контент-пайплайн (.fpf), сетевой слой,
скриптинг (Lua), анимации, AI, аудио, UI и редактор сцены.

## Для кого

- Команда разработки игры (в т.ч. соло-разработчик) на Windows;
- Технические художники и гейм-дизайнеры — через редактор и data-driven
  ассеты (без компиляции кода);
- Скриптеры геймплея — через Lua-скриптинг.

## Какую проблему решает

1. Существующие Rust-движки (Bevy и др.) — «как у всех» по архитектуре и
   не дают полного контроля над рендером, памятью и детерминизмом.
2. Коммерческие движки (UE/Unity) — закрытые, тяжёлые, с чужими
   решениями (GC-паузы, opaque-рендер, привязка к их пайплайну).
3. Нужен движок, где детерминизм, точность больших миров (f64), сетевой
   replay и контроль над VRAM/памятью — first-class свойства, а не хаки.

## Что входит в первую версию (v1.0 «движок готов к игре»)

- Windows, DX12 (primary для release) + Vulkan (primary для dev/CI),
  PBR deferred-рендер с golden-гейтом;
- Архетипная ECS + SchemaRegistry (сериализация/инспектор/репликация);
- Контент-пайплайн: flux-assetc (меши/текстуры/звук/navmesh) → .fpf;
- World partition со стримингом, SaveState с миграциями схем;
- Физика f64 + KCC, анимации, AI (navmesh/BT), аудио-граф, UI, Lua-скриптинг;
- Сеть: loopback + UDP, relevance-ярусы, client-owned персонажи;
- Редактор сцены (egui + viewport RTT), PIE, undo;
- CI-гейты: детерминизм, golden-image, фаззинг, perf-бюджеты, soak.

## Чего сознательно НЕТ в v1 (и почему)

| Не делаем | Причина / точка расширения |
|---|---|
| Консоли (PS/Xbox) | NDA-тулчейны; RHI-trait позволяет добавить бэкенд |
| macOS/Linux как release | Windows — целевой рынок; Vulkan сохраняет возможность |
| Моддинг-песочница (WASM) | Задел зафиксирован (ADR-0025); нет требования |
| Ray tracing, meshlets, virtual textures | После v1 (этап 8+); FeatureSet/MemoryTag зарезервированы |
| Кинематографический секвенсор | После v1 (этап 8+); база готова (ADR-0026) |
| Full SSS, iridescence | Keyword-расширения PBR по потребности |
| Телефоны, VR, веб | Не целевые платформы |

## Принципы (не обсуждаются без ADR)

1. Детерминизм — проверяемый инвариант (fixed tick, seeded-RNG, канон i64,
   CI-харнесс), а не лозунг.
2. Один источник истины на данные: канон позиций, SaveState, VRAM-бюджет,
   канон имён ([canon.md](canon.md)).
3. Контракты важнее реализации: подсистемы не знают друг друга.
4. Graceful degradation: прокси-ресурсы, fallback-шейдеры, pressure-лестница.
5. Всё «своё» — там, где это влияет на ощущение игры; готовое — там, где
   это commodity (кодеки, окно, декодеры).
