# 0044. Рантайм-применение GraphicsSettings: swapchain, граф, пермутации

- Статус: Accepted
- Дата: 2026-11-15
- Затрагивает: flux-graphics
- Supersedes: —

## Контекст

ADR-0016 зафиксировал настройки как данные: `GraphicsSettings::diff` сообщает,
что перестроить, но не описывает, **кто** и **как** применяет изменения к живым
объектам. Пункт 4.8 Roadmap требует рантайм-обвязку: применить swapchain, граф
и пермутации по `SettingsChange`, не пересоздавая Device.

После ADR-0042 кадр — это Render Graph из шести проходов с фиксированными
изображениями. Отключение эффекта (SSAO, bloom, TAA) не должно требовать
нового Device, новых pipeline-ов или ручных барьеров; также нужно, чтобы
`render_scale` менял размер изображений, а не игнорировался.

## Варианты

1. **Пересоздавать Device на любое изменение.** Просто, но ломает PSO-кэш,
   VRAM-бюджет, surface и все внешние хэндлы; противоречит ADR-0016.
2. **Пересобирать всё (swapchain + кадр + pipeline-ы) всегда.** Корректно, но
   дорого: смена только bloom пересоздаёт swapchain и историю TAA.
3. **Целевая перестройка по `SettingsChange`** (выбрано): каждое поле
   настроек отображается на конкретную подсистему; неизменные ресурсы
   остаются живыми.

## Решение

Введены две публичные сущности.

**`render::frame::FrameFeatures`** — набор эффектов кадра `{ ssao, bloom, taa }`,
выводимый из `GraphicsSettings` (`FrameFeatures::from_settings`). Граф
`GpuFrame` строится по этому набору: отключённые проходы не добавляются, но их
изображения остаются зарегистрированными и очищаются нейтральными значениями
(AO = 1, bloom = 0). Следующие проходы читают те же слоты, поэтому
дескрипторные наборы и pipeline-ы не меняются. При выключенном TAA тонемап
пишет прямо в выходной образ (без ping-pong); при включении история TAA
очищается. `GpuFrame::with_features` создаёт кадр сразу с набором,
`GpuFrame::set_features` переключает его на живом кадре и возвращает `true`,
если граф изменится. `GpuFrame::zones()` содержит только активные проходы.

**`render::settings_runtime::SettingsRuntime`** — владелец swapchain и
`GpuFrame`, применяющий настройки. Маппинг `SettingsChange`:

| Поле | Реакция |
|---|---|
| `vsync` / `present_mode` | новый swapchain (create-then-swap, старый жив до успеха) |
| `ssao` / `bloom` / `taa` | `FrameFeatures`, пересборка графа |
| `render_scale` | кадр пересоздаётся под новый размер изображений |
| `shadow_resolution` | зарезервировано: прохода теней ещё нет (4.6) |
| `preset` | инкремент `permutation_generation` (набор пермутаций) |

`GraphicsSettings::diff` расширен: `render_scale` теперь входит в
`SettingsChange::graph`, потому что меняет размер изображений кадра.
Семантика остальных флагов не меняется, Device в `SettingsChange` по-прежнему
отсутствует.

`SettingsRuntime::apply` возвращает фактический `SettingsChange`; при ошибке
RHI прежние настройки и ресурсы остаются в силе. `resize` сначала создаёт кадр
под новый размер, затем меняет swapchain, и только после успеха уничтожает
старый кадр.

## Следствия

- Смена пресета не пересоздаёт Device: `DeviceSignature` и PSO-кэш остаются
  валидными; тесты проверяют неизменность сигнатуры.
- Смена `vsync`/`present_mode` пересоздаёт только swapchain; смена эффектов —
  только граф; смена `preset` — только поколение пермутаций.
- `render_scale` стал частью `graph`-изменения: это уточнение поведения
  ADR-0016, его формулировка не переписывается.
- `shadow_resolution` пока не влияет на кадр: прохода теней нет. Когда 4.6
  добавит тени, `SettingsRuntime::apply` начнёт пересоздавать shadow-ресурсы,
  не меняя контракт `SettingsChange`.
- Null-бэкенд поддерживает только `PresentMode::Fifo`; тесты смены режима
  используют `NullDevice::with_capabilities` с добавленным `Immediate`.
