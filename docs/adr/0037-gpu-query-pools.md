# 0037. GPU query pools: таймстемпы через RHI

- Статус: Accepted
- Дата: 2026-11-13
- Затрагивает: flux-graphics, flux-engine
- Supersedes: —

## Контекст

`GpuProfiler` (I8) описывает зоны кадра, но RHI не умел их измерять: не было
способа записать таймстемпы на GPU и прочитать результаты. Без этого
`FrameStats`/trace остаются CPU-оценкой, а GPU-зоны — мёртвым контрактом.
Нужен минимальный, детерминированный и тестируемый интерфейс, не
привязывающий Render Graph к Vulkan/DX12.

## Варианты

1. **Один timestamp-пул на кадр, пары start/end** (выбрано). Дёшево,
   предсказуемо, напрямую ложится на `GpuZone`.
2. **Пул на зону.** Больше объектов, сложнее бюджет и чтение; выгоды нет.
3. **Pipeline statistics/counters.** Шире по смыслу, но дороже и не нужно
   для G4/профиля кадра.
4. **Таймеры через CPU-события.** Не измеряют GPU-работу.

## Решение

- `QueryPoolDesc { label, count }`, `count ∈ 1..=4096`; `QueryPoolId` —
  детерминированный хэндл.
- `RhiDevice`: `create_query_pool`, `destroy_query_pool`,
  `read_query_pool -> Vec<u64>`.
- `CommandBuffer`: `reset_query_pool(pool, first, count)` и
  `write_timestamp(pool, index)`; запись разрешена только в recording-фазе,
  диапазон и индекс валидируются по ёмкости пула.
- Vulkan: `VK_QUERY_TYPE_TIMESTAMP`, чтение с `TYPE_64 | WAIT` после
  `device_wait_idle`; пул уничтожается вместе с устройством.
- Null: детерминированные значения `index * 1000` нс и та же валидация;
  командный буфер получает копию ёмкостей пулов.
- `GpuProfiler::push_from_timestamps(name, &[u64])` превращает пары
  `[start, end, ...]` в зоны; нечётный хвост игнорируется.
- Профилирование — dev/CI-инструмент: `WAIT` останавливает GPU, поэтому
  чтение выполняется между кадрами, а не в горячем пути.

## Следствия

Плюсы:

- GPU-зоны измеряются реально, `FrameStats`/trace получают источник данных.
- Контракт одинаков для Vulkan и Null, тесты детерминированы.
- Валидация диапазонов ловит ошибки профилирования до драйвера.

Минусы и риски:

- `WAIT` синхронизирует GPU: включать только в профиле/golden-прогонах.
- Нет pipeline statistics и async-чтения — при необходимости новый ADR.
- Валидность таймстемпов зависит от `timestampValidBits` очереди; нули
  трактуются как «не поддерживается», а не как ошибка.

Заделы:

- I8/CI: GPU-зоны в trace и отчёт G4.
- Будущее: async readback без остановки кадра.
