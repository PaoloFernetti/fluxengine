# 0030. Формат SchemaRegistry и ComponentDelta

- Статус: Accepted
- Дата: 2026-11-13
- Затрагивает: flux-ecs (schema, save), flux-scene (save), flux-net (wire),
  flux-editor (инспектор), canon.md
- Связано: ADR-0023 (миграции сейвов), ADR-0010 (SaveState), ADR-0025 (моддинг)

## Контекст

Один и тот же набор метаданных компонента нужен четырём потребителям:
сериализации сцен, SaveState, wire-схеме репликации и инспектору редактора.
Если каждый потребитель описывает компонент по-своему, появляются четыре
источника правды и расхождения, которые обнаруживаются на релизе.

Формат фиксируется сейчас, до первых данных: после появления сейвов и
wire-протокола смена формата — ломающее изменение. Миграционная machinery
(чтение старых ревизий, политики) — этап 5 (№25), здесь только формат.

## Варианты

1. **`serde` на типе компонента.** Плюс: минимум кода. Минус: схема не
   доступна без экземпляра; инспектор не может перечислить поля; UUID поля
   не стабилен; частичная дельта невозможна.
2. **Схемы как данные + отдельный формат на каждого потребителя.**
   Плюс: гибко. Минус: расхождение форматов, дублирование правил порядка
   и ревизий.
3. **Схемы как данные + единый `ComponentDelta`.** Плюс: один источник
   правды, один формат, разные фильтры полей. Минус: нужен дерайв и
   дисциплина атрибутов.

## Решение

Выбран вариант 3.

### Схема

```rust
pub struct ComponentSchema {
    pub type_uuid: TypeId,
    pub schema_rev: u32,
    pub name: &'static str,
    pub fields: Vec<FieldSchema>,   // отсортированы по field_uuid
    pub orphan_policy: OrphanPolicy,
}

pub struct FieldSchema {
    pub field_uuid: FieldId,
    pub name: &'static str,
    pub ty: FieldType,
    pub flags: FieldFlags,          // save / replicated
    pub editor: EditorMeta,         // min, max, slider, category, tooltip, visible
    pub default_ron: Option<String>,
}
```

Правила:

- **`field_uuid` — идентификатор совместимости, не имя.** Ренейм поля
  бесплатен навсегда: меняется `name`, UUID сохраняется. UUID задаётся
  явно (`#[field(uuid = "...")]`) либо детерминированным seed от
  `(type_uuid, seed)`; случайная генерация при компиляции запрещена —
  схемы разъедутся между бинарями.
- **Ревизия.** Смена типа поля или набора полей — `schema_rev + 1`.
  Регистрация `(type_uuid, schema_rev)` с другим содержимым — ошибка.
- **Детерминированный обход.** Поля — по `field_uuid`, реестр — по
  `type_uuid`. Никакой зависимости от итерации `HashMap`.
- **Маркеры.** `#[save]`, `#[replicated]`, модифицируемость (№6/№22) —
  семантика в дерайве, значения в `FieldFlags`; flux-net и моддинг читают
  одно и то же.
- **Граница с сетью.** Registry даёт поля и типы. Квантизация, дельта-
  компрессия и приоритеты — политика flux-net; в `Reflect` они не попадают.

### ComponentDelta

```rust
pub struct ComponentDelta {
    pub entity: EntityUuid,
    pub schema: SchemaRef,          // (type_uuid, schema_rev)
    pub fields: Vec<FieldValue>,    // частичная дельта, по field_uuid
}

pub struct FieldValue { pub field: FieldId, pub value: Value }

pub enum Value {
    F32(f32), F64(f64), I32(i32), U32(u32), I64(i64), U64(u64),
    Bool(bool), String(String),
    Vec3([f32; 3]), DVec3([f64; 3]), WorldPos([i64; 3]),
    Uuid(Uuid), Enum { variant: u32 }, Bytes(Vec<u8>),
}
```

- **Один формат — три потребителя.** SaveState пишет все `save`-поля
  (полная, идемпотентная запись); сеть — `replicated`-поля, изменённые
  с последнего ack (частичная); undo — изменённые поля.
- **Порядок.** `fields` — по `field_uuid`; дельты в журнале — по
  `(entity_uuid, type_uuid, schema_rev, field_uuid)`. Одинаковый вход →
  байт-в-байт одинаковый RON.
- **Неизвестное поле.** Нет `field_uuid` в указанной ревизии — запись
  `OrphanedField` в лог и пропуск; молчаливой потери нет.
- **Старая ревизия.** Чтение допустимо (задел миграций №25); применение —
  политика компонента (`Respawn | Drop | Log`), не дерайв.
- **Кодек этапа 2 — RON** (читаемые фикстуры). Бинарный кодек и wire-
  квантизация — отдельным ADR при появлении сети/релиза; формат полей
  от кодека не зависит.

### Журнал

```rust
pub struct SaveJournal { pub seq: u64, pub entries: Vec<JournalEntry> }
pub struct JournalEntry { pub seq: u64, pub tick: SimTick, pub deltas: Vec<ComponentDelta> }
```

Append-only, `seq` монотонен, `tick` — момент снятия. Орфаны сущностей
обрабатываются `OrphanPolicy` компонента с явным логом.

## Следствия

Плюсы: один источник правды для сейва, сети, undo и инспектора; ренейм
полей не ломает совместимость; дельта частична по построению; формат
пригоден для детерминированной сериализации.

Минусы/риски:

- Дерайв обязан валидировать атрибуты на этапе компиляции (нет UUID поля —
  ошибка, а не случайная генерация).
- `Value` — закрытое перечисление: новый тип поля требует расширения формата
  и ADR (иначе неизвестный вариант у старого клиента).
- RON на этапе 2 не претендует на компактность; бюджет трафика — забота
  flux-net и отдельного ADR.
- Инспектор получает только данные; любая UI-логика — в flux-editor.

Заделы: миграции ревизий (этап 5), бинарный кодек и квантизация (этап 5),
моддинг читает `FieldFlags` как правило модифицируемости (№22).
