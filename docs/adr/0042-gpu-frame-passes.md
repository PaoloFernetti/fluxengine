# 0042. GPU-проходы кадра: push constants, история Render Graph и PSNR-гейт

- Статус: Accepted
- Дата: 2026-11-14
- Затрагивает: flux-graphics
- Supersedes: —

## Контекст

RHI-контракты этапа 4 (ADR-0034, ADR-0035, ADR-0039, ADR-0041) позволяли
собрать отдельный PSO и нарисовать один треугольник, но реальная цепочка
кадра отсутствовала: не было способа передать параметры кадра (солнце,
экспозиция, веса пост-обработки) в шейдеры, Render Graph умел применять
только барьеры, а у TAA не было истории. Без этого G4-критерий «PSNR ≥ 60 дБ
на lavapipe» проверить нечем: golden-гейт сравнивал CPU-эталон с CPU-эталоном.

Ограничения, действующие на момент решения:

- дескрипторные наборы set 0 и раздельные `SampledImage`/`Sampler`
  (ADR-0039, ADR-0041) уже есть, но uniform-буфер на каждый кадр — лишняя
  синхронизация для 64 байт параметров;
- Render Graph компилируется из состояния `Undefined`, а история TAA после
  первого кадра уже лежит в `ColorAttachment`/`ShaderRead` — `oldLayout`
  обязан совпадать с фактическим;
- Null-бэкенд не исполняет шейдеры (ADR-0039), поэтому GPU-эталон может быть
  только на Vulkan;
- CI-раннер lavapipe детерминированнее реального GPU, но квантование
  форматов аттачментов всё равно ограничивает точность сравнения.

## Варианты

1. **Uniform-буфер на кадр** вместо push constants: привычнее, но требует
   staging-обновления и барьера на каждый кадр; для 64 байт это дороже и
   добавляет точку рассинхронизации с командным буфером.
2. **Push constants (выбран)**: `VkPushConstantRange` в layout, запись
   `cmd_push_constants` перед draw; данные живут в командном буфере, барьеров
   не требуется, лимит 64–128 байт достаточен для параметров кадра.
3. **Тела пассов внутри Render Graph** (callback на пасс в графе) вместо
   внешнего `execute_with`: связал бы граф с RHI-вызовами и усложнил бы
   тестирование; выбран внешний хук.
4. **Сброс истории TAA каждый кадр** вместо `compile_with_initial`: проще, но
   TAA перестаёт быть TAA; отклонено.
5. **PSNR против «идеального» CPU-кадра целиком** вместо эталона от readback
   предыдущего прохода: сравнение ловит квантование входов (sRGB-байты,
   fp16) и требует недостижимых 60 дБ; отклонено.

## Решение

### Push constants

- `PipelineDesc::push_constant_size: u32` (по умолчанию 0) и билдер
  `with_push_constants(size)`. Vulkan добавляет `PushConstantRange` со
  stage-flags `VERTEX | FRAGMENT` для graphics и `COMPUTE` для compute;
  `PipelineEntry` хранит размер для валидации.
- `CommandBuffer::push_constants(&[u8])`: данные непустые, кратны 4,
  не больше объявленного размера; требуется активный pipeline (и `begin`).
  Vulkan вызывает `cmd_push_constants`, Null сохраняет байты и отдаёт их
  через `push_constants_bytes()` для диагностики.
- Кадр использует один блок 64 байта (4 × float4): `FrameParams` сериализует
  `1/width`, `1/height`, экспозицию, порог bloom, направление на солнце,
  интенсивность bloom, радиантность, вес TAA и радиус SSAO. Шейдеры
  объявляют его как `[[vk::push_constant]] ConstantBuffer<FrameConstants>`.

### Render Graph: тела пассов и начальные состояния

- `RenderGraph::execute_with(plan, commands, body)` — `execute` делегирует
  ему с пустым телом; `body(pass, commands)` вызывается между барьерами
  пасса и позволяет записать draw/pipeline/наборы, не отдавая графу RHI.
- `RenderGraph::compile_with_initial(&BTreeMap<GraphImageKey, ImageState>)` —
  начальное состояние изображения берётся из карты, иначе `Undefined`.
  `compile()` делегирует с пустой картой. Это делает `oldLayout` истории TAA
  корректным на втором и последующих кадрах.

### Цепочка проходов

`GpuFrame` (модуль `render::frame`) владеет десятью изображениями, шестью
pipeline-ами и пятью дескрипторными наборами:

| Проход | Вход | Выход | Формат выхода |
|---|---|---|---|
| `frame.gbuffer` | — (процедурная поверхность) | RT0 albedo | `Rgba8Srgb` |
| | | RT1 oct-normal | `Rgba16Float` |
| | | RT2 ORM | `Rgba8Unorm` |
| | | depth (Reversed-Z) | `D32Float` |
| `frame.ssao` | depth | SSAO | `Rgba16Float` |
| `frame.lighting` | RT0, RT1, RT2, SSAO | HDR | `Rgba16Float` |
| `frame.bloom` | HDR | bloom | `Rgba16Float` |
| `frame.tonemap` | HDR, bloom | tonemap | `Rgba16Float` |
| `frame.taa` | tonemap, history | output | `Rgba16Float` |

- SSAO хранится в `Rgba16Float`, а не `Rgba8Unorm`: AO-значение 0.5 в UNORM
  квантуется в 127/255, что само по себе даёт PSNR ниже 60 дБ и маскирует
  ошибки математики. Внутренний формат — часть контракта кадра, не ABI.
- TAA — ping-pong: первый кадр читает историю, очищенную в ноль; после кадра
  `history`/`output` меняются местами, а дескрипторный набор TAA
  переписывается на новый выход.
- Все изображения помечены `sampled | render_target | transfer_src`
  (depth — `depth_stencil | sampled | transfer_src`), чтобы readback шёл
  через обычный `copy_image_to_buffer`.

### Исправление viewport/scissor

Dynamic viewport/scissor (ADR-0035) требует явной установки в командном
буфере: `begin_render_pass` теперь выставляет `cmd_set_viewport` и
`cmd_set_scissor` по extent фреймбуфера. Без этого draw не растеризовал
ничего, а PSO-тест этого не замечал, потому что цвет draw совпадал с clear.
`tests/vulkan_pso.rs` усилен readback-проверкой фактического цвета.

### PSNR-методика

- CPU-эталон каждой стадии получает **readback предыдущего прохода**, а не
  идеальные значения: проверяется математика стадии, а не квантование её
  входов.
- 8-битные цели (albedo sRGB, ORM) сравниваются байтами; albedo кодируется
  в sRGB (`encode_srgb_u8`), чтобы избежать линейного квантования.
- fp16-цели декодируются в `f32`; peak = `1.0` для LDR/нормалей и
  `max(reference)` для HDR, чтобы PSNR не зависел от абсолютной яркости.
- Порог — 60 дБ; тест `tests/vulkan_frame.rs` проверяет все стадии, второй
  кадр TAA с историей, чистый validation-лог и `live_resources() == 0`
  после `destroy`.
- На раннере без Vulkan тест завершается успешно (headless-CI), на
  `vulkan-lavapipe` запускается с `FLUX_REQUIRE_VULKAN=1` и падает с
  `::error`-аннотацией.

## Следствия

Плюсы:

- Реальная цепочка кадра с автоматическими барьерами: добавление стадии —
  правка графа, а не ручная синхронизация.
- Push constants убрали staging-обновление и барьер из каждого кадра.
- PSNR-гейт проверяет математику шейдеров против CPU-формул и ловит
  регрессии вида «draw не растеризует» или «формат квантует AO».
- Начальные состояния Render Graph переиспользуемы для любого кадра с
  историей (TAA, temporal upscale, SSR).

Минусы и риски:

- Push constants ограничены 64–128 байтами; рост параметров кадра потребует
  uniform-буфера и нового ADR (контракт `CommandBuffer` не расширяется
  молча).
- Формат SSAO `Rgba16Float` дороже по памяти; на слабых tier-ах возможен
  переход на R8Unorm с другим PSNR-порогом — отдельное решение.
- PSNR-эталон зависит от readback предыдущего прохода: тест проверяет
  стадии по отдельности, а не всю цепочку против одной идеальной картинки;
  полный golden-кадр — в 4.9.
- `GpuFrame` пока процедурный (поверхность из `SV_VertexID`); реальная
  геометрия и culling — 4.5.
- Тела пассов живут вне графа: забытый `match`-рукав даёт
  `unknown frame pass` во время записи, а не при компиляции.
