# FluxEngine — Правила работы с репозиторием

## 1. Модель ветвления: trunk-based

- `main` — единственная долгоживущая ветка, всегда зелёная (CI-гейты).
- Работа — в короткоживущих ветках: `feat/<scope>-<slug>`, `fix/...`,
  `docs/...`, `adr/<NNNN>-<slug>`. Живут не дольше одной задачи.
- Мерж — только через PR (даже соло: PR-описание = дисциплина ревью).
- Squash-мерж в `main`; история `main` — линейная.
- Прямые коммиты в `main` запрещены (кроме аварийного фикса, с постфактум
  ADR/объяснением в PR-ссылке).

## 2. Что попадает в main

Только изменение, прошедшее:
1. Все CI-гейты (fmt, clippy, тесты, линты зависимостей, ADR-чек).
2. Правило ADR: при триггере ([adr/README.md](adr/README.md)) ADR — в том же PR.
3. Канон обновлён, если изменились имена/контракты/форматы.
4. PR-описание: что/почему/как проверено.

Не мержится: код без теста на новый инвариант, «временные» TODO без issue,
изменения форматов без bump версии, красный nightly (если он уже красный —
сначала чинится nightly).

## 3. Версионирование и релизы

- SemVer: `MAJOR.MINOR.PATCH` для движка.
  - MAJOR — несовместимые изменения публичного API/форматов;
  - MINOR — новые возможности, совместимость сохранена;
  - PATCH — исправления.
- Форматы данных имеют СВОИ версии (schema_rev, .fpf format version,
  wire protocol version) — независимо от SemVer движка (ADR-0023).
- Теги: `vX.Y.Z` на коммит в `main`, после зелёного полного CI.
- Релизный артефакт собирается только `tools/flux-build` (детерминированный
  билд, байт-в-байт); хеш паков фиксируется в release-манифесте.
- CHANGELOG.md: раздел Unreleased → по релизу; формат Keep a Changelog.

## 4. Ветки-исключения

- `release/X.Y` — при необходимости поддерживать старую линию; только
  cherry-pick фиксов, без фич.
- Долгоживущие feature-ветки запрещены: всё разбивается на PR-ы.

## 5. Артефакты и мусор

- В репозиторий не попадают: `target/`, `docs/spa/node_modules/`,
  сгенерированные паки, кэши PSO/DXC (см. .gitignore).
- `docs.html` — намеренно коммитируемый артефакт сборки документации
  (single-file, открывается без сервера).
- Golden-ассеты (сейвы, паки, изображения) — в git (малый размер) или
  LFS для бинарных эталонов; правило фиксируется ADR при первом добавлении.
- Крэш-дампы, soak-логи — артефакты CI, не репозиторий.

## 6. Защита main

- CI обязателен для мержа; force-push в main запрещён.
- Красный nightly блокирует мержи до починки (red-green дисциплина).
- Секреты (подписи, ключи распространения) — только в секретах CI,
  никогда в репозитории.
