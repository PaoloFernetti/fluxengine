# FluxEngine — План тестирования

Полная стратегия — в [architecture.md](architecture.md), раздел
«Тестирование и CI» (ADR-0021). Здесь — сводка и «нельзя ломать».

## 1. Уровни и где живут тесты

| Уровень | Где | Частота |
|---|---|---|
| Юнит | `crates/*/src/**` (`mod tests` рядом с кодом) | каждый PR |
| Интеграционные подсистем | `crates/*/tests/` | каждый PR |
| Headless-рендер | `flux-graphics/tests/headless_*` (offscreen, lavapipe) | каждый PR |
| Golden-image | `tests/golden/` + бейзлайны per-раннер | PR (короткий) + nightly |
| Детерминизм | `tests/determinism/` (боты, хеши) | каждый PR (smoke) + nightly |
| Fuzzing | `fuzz/` (cargo-fuzz): .fpf, wire, десериализаторы | непрерывно |
| Perf-бенчмарки | `crates/*/benches/` (criterion) | nightly |
| Soak | отдельный стенд с ботами | еженедельно |

## 2. Критические сценарии («нельзя ломать»)

1. **Детерминизм симуляции**: две headless-ноды, один ввод → идентичный
   хеш стейта после 10k тиков (same-binary; cross-binary nightly).
2. **Экономика кадра**: 0 аллокаций в кадре после прогрева (FrameArena).
3. **GPU-инварианты**: validation layers чистые; «выделено N — освобождено N»
   после каждого рендер-теста.
4. **Стриминг × SaveState**: eviction тайла с изменёнными сущностями не
   теряет дельты; повторная загрузка применяет дифф.
5. **Сейвы**: golden-сейвы всех предыдущих релизов грузятся; миграции
   roundtrip; фаззинг схем не паникует.
6. **Паники**: dev — кадр aborted, процесс жив; release — дамп и чистый
   выход; job-паника не убивает воркер (матрица ADR-0012).
7. **Скриптовая песочница**: вечный цикл гасится instruction limit;
   ошибка скрипта не роняет кадр.
8. **Input**: scancodes (AZERTY), raw mouse delta, deadzone+rescale,
   rebinding roundtrip.
9. **Сеть**: loopback 2 ноды — дельты сходятся; client-owned rewind-replay
   сходится с сервером.
10. **Перф-бюджеты**: тик симуляции, extract, загрузка тайла, применение
    дельты — превышение порога регрессии из Roadmap блокирует.

## 3. Бенчмарк-гейты

Числовые пороги и состав гейтов G1–G7 — **единственный источник:
[Roadmap.md](Roadmap.md)**. Здесь фиксируется только то, где живёт проверка;
дублировать числа запрещено (правило — в [README.md](README.md)).

| Гейт | Проверка живёт в |
|---|---|
| G1 | `flux-core` (FrameArena-трекинг), `flux-engine` (аккумулятор) |
| G2 | `flux-ecs/benches` (criterion) |
| G3 | `tests/determinism` (same-binary smoke) |

| G6 | сценарный бенч `flux-ai`/`flux-anim` |
| G7 | soak-стенд (weekly) |

## 4. Регрессионная политика

- Каждый найденный баг: минимальный воспроизводящий тест → навсегда в наборе.
- Fuzz-крэш: минимальный кейс → regression-корпус, автотест на каждый PR.
- Golden-изменение без PR «visual change» — красный гейт (не «обновили
  бейзлайны»).
- Red-green: красный nightly блокирует мержи в main до починки.

## 5. Чего в тестах не делаем

- Не тестируем фреймтайм на шумных CI-раннерах (только выделенные perf).
- Не сравниваем golden побайтово (PSNR/SSIM + диф-канал).
- Не «обновляем хеш», когда детерминизм разошёлся (это блокер-расследование).
